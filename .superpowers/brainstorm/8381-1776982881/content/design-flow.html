Diseño — Sección 1: Flujo del Sistema

3 casos de detección cold start con Redis Flag + Polling

1

Usuario abre el chat (sin mensajes en UI)

Click burbuja → GET /v1/health/status → 🔄 "Despertando el asistente..." → ✓ Chat normal

La llamada a /health ES el warm-up trigger. Cloud Run arranca al recibir la request. El spinner se muestra mientras la instancia levanta (hasta ~30s).

2

Chat abierto con conversación activa (hasUserMessages)

Poll /health cada 30s mientras chat abierto
⚠️
15 min sin interacción
Muestra mensaje inline: "¿Sigues ahí? El chat entrará en reposo en 5 minutos si no hay actividad."
🔴
Poll detecta shutdown_at flag ó request falla
Muestra UI inline con 3 botones:
Let's continue Start a new chat Close conversation
"Let's continue" → GET /recap → muestra últimos 2 turnos → reanuda sesión
3

Chat abierto en Welcome Screen (sin mensajes)

Poll detecta shutdown → Widget se cierra (isOpen = false) → Próximo open → Caso 1

Sin mensajes no hay contexto que preservar. Cerrar el widget es menos disruptivo que mostrar botones de una sesión vacía.

Redis keys utilizados:
service:shutdown_at — timestamp del SHUTDOWN (TTL: 1h) session:{id}:turns — ya existe (24h TTL)
